storymap-pieces.tsx — Auto-fix + Escalate Flow

The merged workflow: each card is a ReviewLoop (implement → AI-judge → one auto-fix), each milestone ends with an EscalationChain (diagnose → human fallback). Gates remain advisory (onDeny="continue").

Task (agent work) ReviewLoop (implement + auto-fix) Approval gate (human) AI judge / decision Commit (but) EscalationChain Deny / unresolved path

1 · Overall workflow

Each milestone is a Sequence of ReviewLoop cards, an EscalationChain, and a human Approval gate. Ordering is enforced by the Sequence structure (the loops don't forward dependsOn).

2 · A single card — the ReviewLoop (implement → judge → one auto-fix)

The ReviewLoop runs the producer (implement) then the AI judge. If the judge rejects, the loop folds the judge's feedback into the producer and runs one auto-fix (cycle 2). If still rejected, onMaxReached="return-last" hands the unapproved result to the EscalationChain instead of failing the run.

3 · The EscalationChain (diagnose → human fallback)

The diagnose level reads each card's judge output. If every card is approved it sets resolved=true and the chain ends silently. If any card is unapproved it sets resolved=false, which triggers the human fallback Approval — this is the "escalate to me" step.

4 · Gates are still advisory (approve vs. deny)

The milestone gates (env-gate, M1-gate…) are unchanged: a deny is recorded but the workflow continues. The enforcement now lives in the ReviewLoop (AI judge) + EscalationChain (human fallback), not in these gates.

5 · Known limitation + summary

⚠️ No per-card timeout. ReviewLoop does not expose timeoutMs, so a single hung generation (the local Ollama model can stall) will block the run indefinitely. maxIterations=2 bounds attempts, not duration. If a card hangs: smithers cancel <run-id> (or smithers retry-task), then resume. To restore a hard timeout, swap the card ReviewLoop for a raw <Loop> with timeoutMs on the producer Task.
