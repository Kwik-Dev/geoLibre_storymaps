The existing StoryMap renderer is reused as-is. The only change: story objects come from a live API instead of build-time imports. Embedded stories keep working with no server.

Locked decisions (do not re-open these):
(1) GitHub OAuth2 for users, local email+password is admin-only — no public sign-up.
(2) Per-story private | public visibility, chosen by the owner.
(3) Media is either an external URL (S3/Drive/any https) the user supplies, or a local upload to the Go server's disk.
(4) Embedded JSON storymaps keep working without a server (static fallback).
(5) User-created story descriptions are Markdown; embedded stories keep HTML descriptions (dual renderer).

You are implementing Milestone 4 (media upload + serving) of the user-created storymaps feature. M1, M2, M3 are done in `server/`.

SPEC: Read `feature_request_user_created_storymap.md` sections 2 (decision #3 on media), 4.1 (MEDIA_ASSETS table), and any media API surface in section 5. AGENTS.md has the project overview.

YOUR TASK:

4. DELETE /api/media/:aid — soft-delete (set deleted_at); owner or admin only.
5. A chapter's media_ref_type field can be "local" (media_asset_id FK) or "external" (media_external_url). Validate external URLs: must be https://, max 2048 chars.

You are implementing Milestone 7 (hardening + docs) of the user-created storymaps feature. M1–M6 are complete. Read `feature_request_user_created_storymap.md` section 6 (hardening) and `AGENTS.md`.

YOUR TASK:

   - Private story media (GET /media/:aid) checks ownership before serving
   - JWT_SECRET, ADMIN_PASSWORD, GITHUB_CLIENT_SECRET not exposed in any API response or frontend bundle

4. Update README.md: add a "Running the server" section with env vars table, how to build and start the Go server, and how the static fallback (no-server) mode still works.

Tips for keeping context small

  • One milestone per fresh session. Don't load the previous milestone's conversation history.
  • Reference files by path, not by pasting them. The delegation prompts above tell the agent which files to read — don't paste the full file contents.
  • Verify before moving on. After each milestone, confirm the build command passes before starting the next one.
  • Use go build ./... as the fast feedback loop for M1–M4; use npm run build for M5–M6.
  • The feature request file is the source of truth. Each prompt already tells the agent to read it; you don't need to paste it again.
